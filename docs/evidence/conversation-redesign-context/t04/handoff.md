## Scope and files

- `backend/app/services/context/characters/craftsman.json` and `gatherer.json`: rich authored bibles with formative background; values, motives, hopes, fears, contradictions and boundaries; routines, skills/tastes/mannerisms; audience-dependent relationships; voice, humor and emotional tells; ten varied dialogue examples each; explicit knowledge/belief/suspicion/uncertain-memory boundaries; conditional conversational threads; fixed continuity and forbidden game claims. Verified game anchors have separate source references and are excluded from the compact persona. Historical relatives have no present location, inventory, service or playable entity.
- `backend/app/services/context/character_profiles.py`: shared detached source loader and deterministic topic projection. Stable identity, voice, fixed personal anchors and boundaries plus at most two relevant summary cards; generic follow-ups use the latest actual visible user topic, skipping repeated generic follow-ups; greetings do not retrieve old anecdotes. Explicit role allowlist prevents path traversal and unknown-role biography inheritance. Content-hash source revision and `narrative_only` label; no gameplay port or provider call. Optional cards are dropped whole if needed to fit the 4,200-character profile cap, never truncated.
- `backend/app/services/context/craftsman_profile.py`: legacy PROFILE compatibility view derived from the shared authored source; existing fallback wording preserved.
- `backend/app/services/prompts/builder.py`: both prompt paths receive the compact data and shared instructions about direct answers, mixed concerns, relevant optional personal detail, repetition, fixed identity, uncertainty, and unplayed events. Structured identity follows supplied role/name rather than numeric NPC ID when identity evidence exists. Identity-only contexts no longer suppress persona fallback; SQL compact profiles are not duplicated. Structured prompt contract version is v2.
- `backend/app/services/conversation/adapters/context_read.py`: actual SQL NPC role/name and finalized visible history feed the projector after the SQL snapshot closes; detached authored profile source and revisions travel in ContextPacket. No persistence schema, mutation or game-adapter changes.
- `backend/app/services/context/social.py`: narrow standalone personal questions (including childhood, learning, values, motivation and fear); new rules use whole-message matching so mixed practical requests retain authoritative facts. Existing general reflection routing is not redesigned.
- `backend/app/services/validation/service.py`: only complete, explicitly authored personal sentences are exempted from legacy noun guards. Appended mechanics remain visible. Shared guards reject unsupported family claims, game promises, encounter assertions, shops and hidden stashes. No narrative output can grant an item or invoke an operation.
- Tests: new `backend/tests/test_character_profiles.py`; additions in `test_conversation_context_adapter.py`, `test_conversation_generation_adapter.py` and `test_grounded_chat.py`. Real SQL-to-provider prompt capture covers both roles on the same numeric ID and preserves an actual row name. Legacy HTTP-route checks cover real prompt delivery, accepted authored speech, unchanged inventory/relationships and zero proposed state deltas; provider generation alone is scripted.
- Packet, master progress and task graph updated. Existing acceptance criteria, frozen evaluation forms and unrelated working-tree edits preserved. ## Acceptance and limitations

All five T04 acceptance criteria are locally satisfied by authored-source review, real prompt-flow tests, authority separation and adjacent regressions. The context module/release is not declared complete: prior integration and quality gates remain intact.

Legacy validation remains deliberately conservative. Protected family/other-NPC statements use a small set of exact complete authored sentences, not a semantic paraphrase checker. Other natural personal prose remains generated, but a paraphrase containing protected nouns can still be rejected. Full bibles are authoring sources; live profiles retain selected summaries, not every sentence of the source. Unknown wording falls back to the stable character core. No mandatory embedding or semantic model was added.

Live model dialogue quality, repetition rates, model latency and Godot playtesting were not measured in T04. Existing release evidence predates these profiles and must not be represented as evidence of their quality. Generated-canon extraction remains fail-closed as before; authored identity is supplied directly and survives clear/new game without a new persistence mechanism. Changes to output limits, gameplay, UI, capability authorization, generated-canon producers and deployment were outside this task.
